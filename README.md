# Лаборатория «Умного сна» — приложение оператора

Windows-приложение на Flutter для нейробиологической лаборатории, которая
исследует сон на мышах с помощью собственного ЭЭГ-устройства. Приложение
принимает сигнал по BLE, показывает графики, ведёт запись эксперимента с ручной
разметкой и управляет фотобиомодуляцией (ФБМ).

Результат работы оператора — папка эксперимента на диске: `signal.bin`,
`experiment.json`, `journal.ndjson`.

Оператор — биолог или студент, а не сомнолог и не программист. Отсюда почти все
решения ниже.

## Железо

Устройство собрано на АЦП **MAX30003** и микроконтроллере **STM32** (F103),
связь с ПК — по BLE через модуль **JDY-16**. Прошивка и схемотехника плат живут
в отдельном репозитории — [duckduckduck1/Test_eeg](https://github.com/duckduckduck1/Test_eeg).

## Быстрый старт

Нужен Flutter stable (текущая версия — 3.41.4, её же пинует CI).

```bash
flutter pub get
flutter run -d windows
```

Целевая платформа — Windows. Каталоги `android/`, `ios/`, `macos/`, `linux/`,
`web/` остались от шаблона Flutter и не поддерживаются.

## Проверки


## Установщик для Windows

```powershell
powershell -ExecutionPolicy Bypass -File installer\build_installer.ps1
```

Скрипт собирает релизную сборку, берёт версию из `pubspec.yaml` и отдаёт её
Inno Setup — так версия установщика не разъезжается с версией приложения.
Готовый файл появляется в `build\installer\`.

Нужен [Inno Setup 6](https://jrsoftware.org/isdl.php) на машине сборки.

Оператор получает обычный `setup.exe`: мастер установки, ярлык на рабочем
столе, удаление через «Программы и компоненты». Права администратора не нужны —
программа ставится для текущего пользователя.

**Собранный установщик в репозиторий не коммитим.** Он уходит в GitHub
Releases: каждая версия бинарника добавляла бы десятки мегабайт в историю git
навсегда, а очистить историю нельзя. В репозитории живёт только скрипт сборки.

MSIX не используем: он требует подписи, и без покупного сертификата оператору
пришлось бы вручную ставить самоподписанный сертификат перед установкой
программы.

## Структура кода

```text
lib/
  main.dart          точка входа
  main_app.dart      корневой виджет: тема, зависимости, глобальные Cubit
  theme.dart         тёмная тема «Осциллограф» (cyan-акцент, Material 3)
  core/              общее: типы ошибок, модель отсчёта
  features/          доменные фичи: devices, recording, annotation, navigation
  fuetures/          экраны и виджеты: ble_page, main_layout, main_page
  platform/          платформенные адаптеры (ble/)
third_party/         вендорный форк flutter_blue_plus_winrt
```

Внутри фичи зависимости идут в одну сторону: `presentation → application →
domain`, `data → domain`. В `domain` живут модели и **порты** — абстракции над
BLE, файлами и часами. Благодаря им сценарии тестируются на фейках без железа и
без диска. UI не обращается к BLE и файлам напрямую; сценарное состояние — в
BLoC/Cubit, `setState` только для локальной визуальной мелочи.

Остальное документируют сами классы — смотри `///`-комментарии, начиная с
`RecordingBloc`, портов в `features/recording/domain/recording_ports.dart` и
`features/devices/domain/ble_adapter.dart`.

> `fuetures/` — опечатка, доставшаяся от прототипа (там же `proccesing_math`).
> Каталог живой; переименование затронет все импорты и пока не сделано.

## Контракт с устройством

Это единственное, что нельзя вывести из кода приложения: формат общий с
прошивкой в [Test_eeg](https://github.com/duckduckduck1/Test_eeg), и менять его
можно только с обеих сторон сразу.

**Транспорт.** Одна характеристика и на приём сигнала, и на управление:
`0000ffe1-0000-1000-8000-00805f9b34fb`. Устройство рекламирует сервис
`0000ffe0-...` уже в первом advertisement-пакете, а имя (`JDY-16`) может прийти
позже, в scan response — поэтому поиск ловит устройство по имени **или** по
`0xFFE0`. Имя — фильтр поиска, а не доверенный идентификатор.

**Поток.** 250 Гц, один отсчёт — три байта. Длина notify-payload кратна 3, но не
фиксирована (зависит от MTU): разбирать надо группами по 3 байта, а неполный
хвост буферизовать до следующего notify, иначе теряется выравнивание.

**Декодирование.** Три байта складываются в 18-битное знаковое значение:

```text
adc = (b0 << 10) | (b1 << 2) | (b2 >> 6)     старшие 6 бит b2 не несут амплитуду
if adc >= 2^17: adc -= 2^18                  дополнительный код

eeg_uv = adc / 2^17 * (V_REF / GAIN) * 1e7   V_REF = 1.0 В, GAIN = 160
```

Для текущего стенда это ≈ `0.476837` мкВ на единицу АЦП. `V_REF` и `GAIN` —
параметры конкретного тракта, живут в конфигурации устройства, а не литералами
по коду.

**Команда ФБМ.** Пишется в ту же характеристику, четыре байта:

```text
[on_off, pwm_byte, 0x0D, 0x0A]
```

`on_off` — `0x01` включить, `0x00` выключить. `pwm_byte` — яркость: оператор
задаёт уровень `1..99`, приложение считает `pwm_byte = round(level * 255 / 100)`.
`0x0D 0x0A` (CR LF) обязательны.

## Что приложение пишет на диск

Оператор выбирает свою рабочую папку и вводит название эксперимента — папка с
данными называется так же. Выбрал `ФБМ_Группа1_Контроль`, ввёл `Мышь 1`:

```text
ФБМ_Группа1_Контроль/
  Мышь 1/
    signal.bin        отсчёты int32 little-endian, микровольты, 250 Гц, после фильтров
    signal_raw.bin    те же отсчёты, но как пришли с устройства, без фильтров
    experiment.json   метаданные: фильтры, ШИМ, сегменты, разрывы, метки, события ФБМ
    journal.ndjson    append-only журнал событий записи
    readme.txt        пояснение для того, кому передадут данные: формат файлов,
                      расшифровка полей experiment.json, словарь меток
```

Название обязательно и проверяется как имя папки (запрещённые символы Windows,
зарезервированные имена). Повтор названия отклоняется — иначе запись легла бы
поверх уже собранных данных. Рядом с названием в `experiment.json` лежит
`experiment_id` — машинный ULID: он привязывает строки журнала к записи и
переживает переименование папки.

Оба `.bin` содержат только амплитуды — время, сегменты и метки живут в JSON,
`sample_count = размер / 4`. Файлы одной длины: по индексу отсчёта в одном
смотрится тот же отсчёт в другом.

`experiment.json` пишется атомарно (временный файл + переименование) — при
остановке и, кроме того, раз в полминуты во время записи. Периодический снимок
нужен, чтобы после падения приложения или выключения питания папка осталась
пригодной для разбора: в снимке активный сегмент закрыт текущим счётчиком.
Сегменты задают полуоткрытые диапазоны `[start_sample, end_sample)`; метки и
события ФБМ ссылаются на глобальный индекс отсчёта и обязаны попадать внутрь
своего сегмента.

Выгрузку по сети приложение не делает — оператор забирает папку сам.

## Ключевые решения

Короткий список того, что легко откатить по незнанию и что этого делать не надо.

- **Сигнал пишется в двух версиях.** `signal.bin` — после фильтров (с ним
  работают), `signal_raw.bin` — как пришёл с устройства. Фильтр необратим,
  поэтому сырой сигнал храним: по нему можно перефильтровать иначе. Применённые
  фильтры фиксируются в `experiment.json`. Цена — ещё ~3.6 МБ в час.
- **Фильтр записи и фильтр графика — разные.** Запись использует потоковый
  Butterworth по одному отсчёту; график перефильтровывает весь буфер целиком и
  для записи непригоден.
- **Обрыв связи → новый сегмент и `gap`, без синтетических отсчётов.** Нули за
  время разрыва не дописываются: дырка честно описана в `gaps`.
- **ФБМ работает только во время записи** и гаснет на остановке и на обрыве —
  чтобы свет всегда был привязан к эксперименту и попадал в его журнал.
- **Метки — про наблюдаемое поведение** (спит, ест, бегает), а не про стадии сна.
  Оператор биолог: по сигналу он ничего не скажет, а поведение в клетке опишет
  надёжно. Скоринг по ЭЭГ — задача постобработки, не оператора.
- **Поиск устройства фильтрует по имени ИЛИ `0xFFE0`.** Требовать оба признака
  нельзя: в первом adv-пакете имени ещё нет, и устройство ищется минутами.
- **Анимация графиков выключена** (`duration: Duration.zero`) — иначе живой
  график дёргается.
