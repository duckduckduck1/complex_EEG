# Разметка

Документ описывает реализацию ручной разметки в Flutter-приложении.

---

## BLoC

```text
RecordingBloc
```

В MVP разметка во время активной записи живёт в `RecordingBloc`, потому что
метки должны атомарно писаться в тот же `journal.ndjson` и попадать в финальный
`experiment.json` вместе с сегментами записи.

`RecordingState` содержит:

```text
labels
activeDraftLabel
```

`RecordingAnnotationDialog` не меняет данные напрямую. Виджет только показывает
состояние `RecordingBloc` и отправляет события:

```text
RecordingStateLabelStarted
RecordingActiveStateLabelClosed
RecordingPointLabelAdded
RecordingExcludeIntervalAdded
RecordingAnnotationDeleted
```

Отдельного bloc у разметки нет: метка привязана к текущему сегменту и счётчику
отсчётов записи, поэтому источник «сейчас» — состояние `RecordingBloc`, и вся
логика живёт там же. В `features/annotation` остались модели, справочник типов
меток и окно разметки. Справочник передаётся в `RecordingBloc` явно, что
позволяет подменять его в тестах.

---

## Типы меток

### Метки-состояния

Интервальные состояния:

```text
sleep
rest
eating
grooming
locomotion
custom
```

### Точечные события

```text
startle
movement
custom_event
```

### Бракованные участки

Брак хранится как интервальная метка исключения:

```text
bad_segment
```

Бракованный участок не меняет `signal.bin` и не удаляет отсчёты — это пометка
для последующего анализа.

### Справочник

Запись справочника:

```text
label_type_id
kind: state | event | exclude
display_name
color
is_active
sort_order
```

Сейчас в коде есть только seed-набор `defaultLabelTypes`, который передаётся в
`RecordingBloc` явным параметром. Настраиваемый справочник — отдельная задача;
когда появится, он должен приходить тем же путём, без скрытых глобальных
singleton.

Неактивные метки остаются читаемыми для старых экспериментов.

## Система координат

Каждая метка привязана к существующему сегменту:

```text
segment_id
segment_sample_index
```

Интервальная метка:

```text
segment_id
start_segment_sample_index
end_segment_sample_index
```

Правила:

- интервал задан как `[start, end)`;
- интервал не может пересекать границу сегмента;
- точечное событие должно быть внутри сегмента;
- метки не создают и не меняют сегменты.

Для финального `experiment.json` приложение дополнительно пишет глобальные
координаты `sample_index` или `start_sample`/`end_sample`. Эти значения должны
лежать внутри диапазона `segments[].start_sample..end_sample`.

## Разметка во время записи

Во время записи:

1. пользователь открывает окно меток из панели записи;
2. приложение фиксирует текущий сегмент и локальный индекс отсчёта;
3. `RecordingBloc` создаёт метку и пишет `annotation_created` в журнал;
4. при закрытии state-метки приложение пишет `annotation_updated`;
5. при удалении метки приложение пишет `annotation_deleted`;
6. при остановке записи финальный `experiment.json` получает только закрытые
   метки.

Открытая метка-состояние хранится как `activeDraftLabel`. Черновая метка может
быть в журнале, но не может попасть в финальный `experiment.json` без
`end_sample`.

Если обрыв BLE произошёл при открытой метке-состоянии:

- метка закрывается на конце текущего сегмента;
- после ручного переподключения пользователь может начать новую метку;
- приложение не достраивает поведение за время разрыва.

## Состояние UI

UI не хранит бизнес-состояние разметки в `StatefulWidget`. Локальные
`TextEditingController` допустимы только для полей формы до отправки события в
BLoC.

Виджет разметки активной записи подписывается на:

```dart
BlocBuilder<RecordingBloc, RecordingState>(...)
```

Виджет не открывает файлы, не вызывает BLE, не пишет JSON и не пересобирает пакет
эксперимента. Все побочные эффекты идут через BLoC и storage-порты.

---

## Проверки реализации

- интервальная метка не может пересечь границу сегмента;
- точечное событие вне сегмента отклоняется;
- обрыв закрывает открытую метку-состояние;
- черновая метка не попадает в финальный `experiment.json`;
- удаление метки журналируется;
- сохранение разметки пересобирает JSON атомарно;
- неактивная метка справочника всё ещё отображается в старых экспериментах;
- бракованный участок хранится как разметка, а не как изменение сигнала.
