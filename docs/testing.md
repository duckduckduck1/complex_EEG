# Тестирование

Тестовая стратегия приложения: что проверяем, чем подменяем железо и какие
сценарии обязаны быть зелёными. Документ описывает текущее состояние тестов.

## Принцип

Проверяем не внешний вид, а надёжность записи, разметки и работы с устройством.
Тесты идут **без железа и без реального диска**: всё внешнее спрятано за портами
из `domain`, а в тестах вместо реализаций подставляются фейки. Поэтому вся
критичная логика живёт в BLoC и доменных моделях, а не в виджетах.

## Как запускать

Из корня репозитория:

```bash
flutter analyze
flutter test
dart format --set-exit-if-changed lib test
```

Те же команды гоняет CI на каждый push и PR.

## Структура

```text
test/
  features/   доменные фичи: devices, navigation, recording
  fuetures/   экраны: ble_page, main_layout, main_page
  platform/   адаптер BLE поверх flutter_blue_plus
```

Структура повторяет `lib/`, включая унаследованную опечатку `fuetures`.

## Уровни

**Модульные** — декодер отсчётов (`ble_sample_decoder_test`), отображаемое имя
устройства, генерация `experiment_id`.

**Тесты BLoC** — для каждого: начальное состояние, успешный сценарий, сбойный
сценарий, повторные события, освобождение ресурсов. Самые содержательные —
`recording_bloc_test`: сегменты и разрывы, фильтрованная запись, ФБМ, метки,
финальный `experiment.json`.

**Виджет-тесты** — экран реагирует на состояние BLoC, кнопки шлют события,
компоновка не ломается на узкой ширине, ни один виджет не лезет в файлы или BLE
напрямую.

## Фейки

```text
_FakeAdapter                BLE-адаптер: поиск и подключение
_FakeConnection             соединение: поток пакетов, обрыв, приём команд
_FakeFbmTransport           транспорт ФБМ: запоминает вызовы setLed
_MemoryExperimentStorage    хранилище в памяти вместо диска
_FakeClock                  детерминированное время
_FixedIdGenerator           предсказуемый experiment_id
_FakeRecordingBlocFactory   подмена фабрики записи на вкладке
```

`_FakeClock` нужен, чтобы тесты сегментов и разрывов были детерминированными.
`_MemoryExperimentStorage` позволяет проверять журнал и финальный JSON без
файловой системы.

## Сценарии, которые обязаны быть зелёными

- старт и остановка записи на поддельном потоке BLE;
- обрыв связи закрывает сегмент, добавляет `gap` и **не** достраивает
  синтетические отсчёты;
- переподключение открывает новый сегмент;
- в `signal.bin` уходит фильтрованный сигнал;
- ФБМ работает только в статусе `recording` и гаснет на остановке и обрыве;
- метка-состояние закрывается на остановке и на обрыве и не пересекает границу
  сегмента;
- финальный `experiment.json` содержит фильтры, сегменты, `gaps`, `labels`,
  `fbm_events`;
- переключение вкладок не размонтирует живой график.
