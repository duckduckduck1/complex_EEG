# linux.md

## Linux-среда

Linux-среда — базовый слой, на котором живёт серверная часть системы. На текущем
этапе это Ubuntu VM с доступом по SSH. Позже та же структура должна переноситься
на физический сервер или другую площадку без переписывания всей эксплуатации.

Задача этого слоя — дать предсказуемую, безопасную и удобную основу для Docker,
Ansible, мониторинга и бэкапов.

---

## Сквозные принципы

1. **Сервер не настраивается как личный ноутбук.** На машине должны быть только
   нужные пользователи, сервисы, директории и порты.

2. **Доступ должен быть контролируемым.** Работа через SSH, без лишних открытых
   сервисов.

3. **Данные отделены от приложения.** Файлы экспериментов, PostgreSQL volume,
   бэкапы и логи должны жить в понятных директориях вне контейнеров.

4. **Ручные действия потом переносятся в Ansible.** Если шаг нужен для работы
   сервера, он должен быть описан так, чтобы его можно было автоматизировать.

---

## 1. Базовая машина

На текущем этапе используется:

- Ubuntu VM;
- доступ по SSH;
- один серверный узел;
- локальная отладка всей серверной части;
- последующий перенос на выбранную руководством инфраструктуру.

Минимальные требования к машине фиксируются позже после первых нагрузочных и
дисковых оценок. На архитектурном уровне важно, что сервер должен иметь
достаточно места для файлов экспериментов, PostgreSQL, результатов обработки и
бэкапов.

---

## 2. Пользователи и доступ

На сервере должны быть разделены:

- пользователь для администрирования;
- пользователь или группа для работы приложения;
- права на директории с данными;
- права на директории с бэкапами;
- доступ к Docker.

SSH-доступ должен быть ограничен только нужными пользователями. Пароли, токены и
ключи не должны храниться в репозитории.

---

## 3. Директории

На сервере нужны отдельные директории:

- код и конфигурация проекта;
- данные экспериментов;
- PostgreSQL volume;
- результаты обработки;
- логи приложения;
- бэкапы файлов экспериментов;
- бэкапы PostgreSQL;
- конфигурации мониторинга.

Директории должны быть названы и расположены так, чтобы было понятно, что можно
пересоздать, а что является ценными данными.

Главное правило: контейнер можно удалить и пересобрать, данные экспериментов —
нельзя потерять.

---

## 4. Сеть и firewall

На сервере должны быть открыты только нужные порты:

- SSH для администрирования;
- HTTP/HTTPS для веб-интерфейса и API;
- внутренние порты сервисов только внутри Docker-сети;
- мониторинг — по выбранной схеме доступа.

PostgreSQL не должен быть открыт наружу без необходимости. По умолчанию он должен
быть доступен только сервисам внутри серверной сети.

---

## 5. Системные обновления

Нужно разделять:

- обновления операционной системы;
- обновления Docker и системных пакетов;
- обновления приложения;
- обновления схемы БД;
- обновления пайплайна обработки.

Обновления ОС не должны неожиданно ломать работу приложения. Перед важными
обновлениями должны быть актуальные бэкапы и понятный способ отката или
восстановления.

---

## 6. Логи на уровне Linux

На уровне Linux важны:

- системные логи;
- логи SSH;
- логи Docker;
- логи перезапуска сервисов;
- сообщения о нехватке места на диске;
- ошибки файловой системы.

Эти логи нужны для runbook и разбора инцидентов.

---

## 7. Что не входит в Linux-слой

- логика приёма экспериментов;
- валидация данных;
- обработка ЭЭГ;
- веб-интерфейс;
- бизнес-логика сервера;
- хранение секретов в открытом виде;
- ручная настройка, которая не будет позже перенесена в Ansible.
