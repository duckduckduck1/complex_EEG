# valid.md

## Валидация

Валидация — обязательный этап между загрузкой эксперимента и сохранением его как
принятого сервером. Её задача — проверить, что пакет эксперимента целый,
структурно корректный и пригоден для хранения и последующей обработки.

Валидация не исправляет данные молча. Если пакет некорректен, сервер возвращает
ошибку с причиной, а эксперимент не переводится в статус `accepted`.

---

## Сквозные принципы

1. **Валидация стоит до принятия эксперимента.** Пока проверка не пройдена,
   эксперимент не считается принятым сервером.

2. **Исходные данные не изменяются.** Валидатор читает файлы, проверяет связи и
   структуру, но не переписывает `signal.bin` и `experiment.json`.

3. **Ошибки должны быть понятными пользователю.** Приложение должно показать не
   только факт ошибки, но и её причину.

4. **Проверка защищает следующие этапы.** Пайплайн обработки и веб-интерфейс не
   должны получать эксперимент с битой структурой.

---

## 1. Вход валидатора

Валидатор получает пакет эксперимента после завершения загрузки:

- `signal.bin`;
- `experiment.json`;
- опционально `journal.ndjson`;
- опционально `app.log`;
- техническую информацию загрузочной сессии;
- `experiment_id`.

---

## 2. Минимальные проверки

2.1. Наличие обязательных файлов:

- `signal.bin`;
- `experiment.json`.

2.2. Читаемость `experiment.json`.

2.3. Наличие обязательных полей в JSON:

- `experiment_id`;
- метаданные эксперимента;
- параметры записи;
- sample rate;
- список сегментов;
- информация о разрывах;
- разметка, если она есть;
- события ФБМ, если они есть.

2.3.1. Защитная проверка `experiment_id`: валидатор сверяет, что эксперимент с
       таким `experiment_id` не был принят ранее. Основная проверка дублей
       выполняется сервером до старта загрузки, но повторная проверка на этапе
       валидации защищает систему от гонок, ручных ошибок и некорректных
       загрузочных сессий.

2.4. Проверка `signal.bin`:

- файл существует;
- файл не пустой;
- размер файла соответствует последовательности int32;
- количество отсчётов можно вычислить однозначно.

2.5. Проверка сегментов:

- `start_sample` и `end_sample` не выходят за пределы бинарника;
- диапазоны сегментов заданы как `[start_sample, end_sample)`;
- `start_sample < end_sample`;
- сегменты не пересекаются;
- порядок сегментов соответствует порядку записи.

2.6. Проверка разрывов:

- разрыв ссылается на существующие соседние сегменты;
- разрыв не превращается в искусственные данные;
- длительность разрыва, если указана, помечается как справочная.

2.7. Проверка разметки:

- метки ссылаются на существующий `segment_id`;
- точечные события ссылаются на существующий `segment_sample_index`;
- интервальные метки не выходят за пределы сегмента;
- интервальные метки не пересекают границу сегмента.

2.8. Проверка событий ФБМ:

- событие ссылается на существующий сегмент;
- `segment_sample_index` находится внутри сегмента;
- параметры стимуляции, если есть, читаются корректно.

---

## 3. Результат валидации

Если проверка успешна:

- эксперимент получает статус `accepted`;
- исходный пакет передаётся в хранилище данных;
- сервер может запускать пайплайн обработки.

Если проверка неуспешна:

- эксперимент получает статус `validation_failed`;
- сервер сохраняет причину ошибки;
- приложение и веб-интерфейс могут показать эту причину пользователю;
- пайплайн обработки не запускается.

---

## 4. Ошибки валидации

Ошибки должны быть конкретными:

- нет обязательного файла;
- JSON не читается;
- нет обязательного поля;
- размер бинарника некорректен;
- сегмент выходит за пределы `signal.bin`;
- сегменты пересекаются;
- метка ссылается на несуществующий сегмент;
- интервальная метка пересекает границу сегмента;
- событие ФБМ ссылается на несуществующий отсчёт;
- `experiment_id` уже принят сервером — защитная повторная проверка после
  серверной проверки на этапе создания загрузочной сессии.

---

## 5. Что валидатор не делает

- не исправляет `experiment.json` автоматически;
- не редактирует разметку;
- не склеивает сегменты;
- не заполняет разрывы искусственными данными;
- не фильтрует сигнал;
- не запускает обработку;
- не принимает научных решений о качестве эксперимента.
