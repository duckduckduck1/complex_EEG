# utils.md

## Утилиты

Утилиты — это дополнительные инструменты анализа сигнала в реальном времени.
Они помогают экспериментатору и исследователю смотреть на текущую запись шире,
чем через график сырого сигнала: видеть частотную структуру, динамику мощности и
результат фильтрации.

Утилиты работают поверх текущего буфера сигнала и сохранённых данных
эксперимента, но не изменяют исходный бинарник. Записанный сигнал остаётся
исходной версией данных, а результаты утилит используются для диагностики,
просмотра и последующего анализа.

---

## Сквозные принципы

1. **Утилиты не являются источником истины.** Источник истины — файл
   эксперимента: бинарник сигнала + JSON-описание. Утилиты только отображают и
   вычисляют производные представления данных.

2. **Утилиты не изменяют записанный сигнал.** Любая фильтрация, спектральный
   анализ или пересчёт применяются только для отображения и анализа. В бинарнике
   остаются исходные обработанные значения амплитуды в мкВ.

3. **Утилиты не выполняют автоматическую разметку.** Они могут помогать
   исследователю видеть признаки состояний, но не определяют фазы сна и не
   принимают решений вместо оператора.

4. **Утилиты работают с сегментами честно.** Разрывы связи не склеиваются.
   Расчёты выполняются внутри доступных непрерывных участков сигнала; область
   разрыва не заполняется искусственными данными.

---

## 1. Частотный спектр

1.1. Отображение частотного спектра для текущего выбранного окна сигнала.

1.2. Спектр показывает, какие частотные компоненты присутствуют в сигнале в
     выбранный момент записи.

1.3. Окно анализа выбирается из текущего буфера записи или из открытого
     сохранённого эксперимента.

1.4. Спектр используется как исследовательская и диагностическая утилита: он
     помогает видеть доминирующие частоты, ритмы и изменения структуры сигнала.

1.5. Если выбранное окно попадает на разрыв между сегментами, анализ выполняется
     только по доступной непрерывной части сигнала либо требует выбора другого
     окна.

## 2. Мощность по диапазонам частот и динамика во времени

2.1. Расчёт мощности сигнала в заданных частотных диапазонах.

2.2. Диапазоны используются как спектральные показатели, полезные для анализа
     фаз сна и других состояний, но не являются автоматическим определением этих
     состояний.

2.3. Набор частотных диапазонов должен быть настраиваемым, потому что рабочие
     диапазоны зависят от объекта исследования, методики и решений лаборатории.

2.4. Для каждого диапазона отображается текущая мощность и её изменение во
     времени.

2.5. Динамика мощности помогает видеть, как меняется состояние сигнала в ходе
     эксперимента, без автоматической классификации и без изменения разметки.

2.6. Расчёты выполняются по непрерывным сегментам. Интервалы разрывов не
     достраиваются и не используются как данные.

## 3. Спектрограмма

3.1. Спектрограмма показывает изменение частотной структуры сигнала во времени.

3.2. По горизонтали отображается время, по вертикали — частота, цветом —
     мощность частотной компоненты.

3.3. Спектрограмма помогает видеть переходные участки, устойчивые ритмы и
     изменения мощности частотных диапазонов на протяжении записи.

3.4. При наличии разрыва связи спектрограмма должна явно показывать отсутствие
     данных, а не соединять соседние сегменты в непрерывную картинку.

3.5. Спектрограмма доступна как для live-записи, так и для просмотра сохранённого
     эксперимента.

## 4. Предпросмотр фильтров

4.1. Предпросмотр фильтров позволяет посмотреть, как сигнал будет выглядеть после
     применения выбранной фильтрации.

4.2. Фильтры применяются только к отображению и расчётам в утилитах. Исходный
     бинарник эксперимента не перезаписывается.

4.3. В интерфейсе должно быть ясно видно, что пользователь смотрит
     отфильтрованное представление, а не изменённые исходные данные.

4.4. Возможные типы фильтров для предпросмотра:
     - notch-фильтр для сетевой наводки;
     - band-pass;
     - high-pass;
     - low-pass.

4.5. Конкретные параметры фильтров фиксируются позже на этапе описания
     реализации.

## 5. Технические логи

5.1. Технические логи не являются отдельной пользовательской аналитической
     утилитой, но нужны для диагностики работы приложения.

5.2. В логах фиксируются служебные события: подключение и отключение устройства,
     обрыв BLE, ручное переподключение, ошибки записи, восстановление после
     сбоя, старт и остановка эксперимента.

5.3. Логи помогают разбирать проблемы записи и связи, но не подменяют журнал
     событий эксперимента.

5.4. Журнал событий эксперимента остаётся частью файла эксперимента, а
     технические логи относятся к диагностике работы приложения.

---

## Что не входит в блок утилит

- автоматическое определение фаз сна;
- ML-классификация состояний;
- автоматическая разметка поведения;
- изменение исходного бинарного сигнала;
- принятие решений вместо оператора.
