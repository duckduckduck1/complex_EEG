# Flutter-приложение оператора

Раздел описывает реализацию Windows Flutter-приложения для локальной записи,
разметки, диагностики и подготовки пакета эксперимента для последующей ручной
загрузки через Web UI сервера.

---

## Обязательное архитектурное правило

Во всём приложении используется BLoC.

Правило:

- UI не хранит бизнес-состояние через `setState`;
- состояние экрана живёт в `Bloc` или `Cubit`;
- виджет отправляет события и отображает состояние;
- доступ к BLE, файлам, БД, серверу и DSP идёт через репозитории/сервисы;
- один эксперимент устройства управляется отдельным набором экземпляров BLoC.

`setState` допустим только для локальной визуальной мелочи, которая не влияет на
данные, запись, отправку, разметку, подключение или навигацию.

## Базовые решения первого стенда

- Платформа: Windows desktop.
- UI: Flutter.
- Управление состоянием: `flutter_bloc`.
- Навигация: слой маршрутов вызывает только провайдеры BLoC, не бизнес-логику.
- Локальный индекс экспериментов: встроенная локальная БД или JSON-файл индекса,
  решение уточняется при создании кода; контракт описан в `storage.md`.
- Источник истины для эксперимента: папка эксперимента.
- Источник истины во время записи: `signal.bin` + `journal.ndjson`.
- Контракт финального экспорта: `signal.bin` + `experiment.json`.
- Передача на сервер: ручной экспорт пакета; загрузка выполняется через Web UI.

---

## Главные ограничения

- Сервер не нужен для записи.
- Каждое BLE-устройство ведёт независимый эксперимент.
- Разрывы BLE не склеиваются.
- `signal.bin` содержит амплитуды `int32` в мкВ.
- `experiment.json` ссылается на бинарник через индексы отсчётов.
- Все пользовательские действия, которые меняют эксперимент, пишутся в
  append-only журнал.
